Large Document — Offloaded > 2,000 chars · KV reference ingestion
Model Acts
Calls web_fetch("https://example.com/article")
Model Receives
Compact stub — stub includes wiki tool instructions alongside rlm_query
── CONTENT OFFLOADED ──────────────────── tool: web_fetch source: https://example.com/article chars: 18,432 key: kv_7f3a9b2c threadId: f50450ee-582d-49b3-9bb2 type: technical reference rlm: yes ─ summary, concepts, questions… ──────── to ask questions: rlm_query(<question>, {threadId, toolKey}) to ingest into wiki: wiki_create_page({ title: <title>, threadId: "f50450ee-...", toolKey: "kv_7f3a9b2c" }) wiki_update_page({ pageId: <id>, threadId: "f50450ee-...", toolKey: "kv_7f3a9b2c" })
Model Decides
The user asked to save this article to the wiki. I'll call wiki_create_page with the KV reference — no need to load the full content.
Model Acts
Calls wiki tool with KV reference — full content stays in the store
wiki_create_page({ title: "Distributed Systems", threadId: "f50450ee-582d-49b3-9bb2", toolKey: "kv_7f3a9b2c" })
Inside the tool  ·  invisible to model
1
Fetch from KV store
Retrieves full 18,432-char body using threadId + toolKey
2
Text split
Divides into manageable chunks (~2,000 chars each) using recursive character splitting, preserving paragraph and section boundaries
3
Sub-agent processes chunks
Each chunk is formatted and transformed for wiki storage — headings normalised, links resolved, frontmatter extracted
4
Write to wiki
For a single-page document: one page created. For very large documents: multiple pages created with auto-generated index
Model Receives
Compact result — full body never entered context
status: created chunks: 8 processed pages created: 1 pageId: wiki_b8e1 path: /wiki/distributed-systems
Turn Complete
Page created. Only the stub (~800 chars) and the compact result committed to checkpoint.
Checkpoint footprint after turn
Inline path
~18,432 chars (full content passed to wiki tool) + tool result · accumulates across turns
KV reference path
~800 chars stub + ~120 chars result · full content processed inside the tool, never in checkpoint
Updated tool interface — wiki_create_page & wiki_update_page
Current — raw content corpus
// Model must pass full content in context wiki_create_page({ title: z.string(), content: z.string() .describe( 'Full article text.' ) })
Content must exist in context window before the tool call can be made. For large documents this exhausts context budget before any wiki write occurs.
Updated — raw content or KV reference
// Model chooses: inline text or KV ref wiki_create_page({ title: z.string(), corpus: z.union([ // inline (small documents) z.object({ raw: z.string() }), // KV reference (large documents) z.object({ threadId: z.string(), toolKey: z.string() }) ]) })
When threadId + toolKey is supplied the tool fetches, splits, and processes content internally. The model only receives the compact result — full body never enters the context window.
