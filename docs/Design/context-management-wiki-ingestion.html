Large Document — Single Page > 2,000 chars · one coherent topic
Model Acts
Calls web_fetch("https://example.com/article")
Model Receives
Compact stub with wiki ingestion instruction
── CONTENT OFFLOADED ────────────────── tool: web_fetch chars: 18,432 key: kv_7f3a9b2c threadId: f50450ee-582d-49b3-9bb2 type: technical reference rlm: yes ─ summary, concepts, questions… ────── to ingest into wiki: wiki_create_page({ title: <title>, threadId: "f50450ee-...", toolKey: "kv_7f3a9b2c" })
Model Decides
Single article on one topic — one wiki page is the right shape.
Model Acts
Passes KV reference — full content stays in store
wiki_create_page({ title: "Distributed Systems", threadId: "f50450ee-...", toolKey: "kv_7f3a9b2c" })
Inside the tool  ·  invisible to model
1
Fetch from KV store
Retrieves full 18,432-char body via threadId + toolKey
2
Structure analysis
Scans for H1/H2 headings — finds sub-sections within one topic. No section boundary warrants a separate page.
3
Text split → 8 chunks
Recursive character split (~2,300 chars each), preserving paragraph boundaries
4
Sub-agent formats chunks
Headings normalised, links resolved, wiki frontmatter added
5
Write → 1 page
All chunks assembled into /wiki/distributed-systems
Model Receives
Compact result — 18K never entered context
status: created chunks: 8 processed pages created: 1 pageId: wiki_b8e1 path: /wiki/distributed-systems

One page created. Stub + compact result in checkpoint (~920 chars total).

Updated tool interface — wiki_create_page & wiki_update_page
Current — raw content corpus
// Model must pass full content in context wiki_create_page({ title: z.string(), content: z.string() .describe( 'Full article text.' ) })
Content must exist in context window before the tool call can be made. For large documents this exhausts context budget before any wiki write occurs.
Updated — raw content or KV reference
// Model chooses: inline text or KV ref wiki_create_page({ title: z.string(), corpus: z.union([ // inline (small documents) z.object({ raw: z.string() }), // KV reference (large documents) z.object({ threadId: z.string(), toolKey: z.string() }) ]), layout: z.enum(['single', 'multi']) .optional() // omit to auto-detect from document // structure (H1/H2 section count) })
When threadId + toolKey is supplied the tool fetches, splits, and processes content internally. layout can be set explicitly by the model (informed by the stub summary) or omitted to let the tool auto-detect based on H1/H2 section count. The model only receives the compact result — full body never enters the context window.
