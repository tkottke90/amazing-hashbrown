Compact Stub Format Reference
tool / source / chars Auto
YAML-style frontmatter populated by the interceptor from the tool call metadata. tool is the tool name, source is the URL or resource identifier, chars is the character count of the original response before offloading.
key / threadId Auto
key is the K/V store lookup address (UUID-derived, prefixed kv_) written at intercept time. threadId is the current thread identifier — together they form the fully-qualified address for rlm_query mode 3.
summary Generated
3–5 sentence abstract produced by a fast model (Haiku-class) at intercept time. Must convey the document's scope, key conclusions, and anything structurally notable. Written as an abstract, not a blurb — generic phrases like "explores the topic of…" are disqualifying. This is the model's primary signal for deciding whether to query at all.
key concepts Generated
Named, specific concepts the document covers: algorithms, frameworks, standards, technical terms. Generic category nouns (e.g. "systems", "design") are disqualifying — each entry must be specific enough that a question could be formulated against it. Typically 4–7 items.
entities Generated
Strict named entities only: people, organizations, products, standards bodies, RFC numbers. Generic nouns do not qualify. Omitted entirely if the document has no meaningful named entities — an empty list is worse than no field.
document type / suitable for rlm Generated
document type classifies the content's format and genre: technical reference, tutorial, news article, API response, data export, code file, etc. suitable for rlm is a yes/no flag set by the metadata generator — no when the content is non-prose (JSON, CSV, diff, raw data) where RLM chunking and embedding will not produce meaningful answers. This flag tells the model not to attempt rlm_query against this stub.
questions answered Generated
3–5 specific, answerable questions the document actually addresses — generated by the metadata model, not templated. This is the most important field: it lets the model identify whether its task overlaps with the document's Q&A surface and formulate a precise rlm_query call without having read the content. Vague questions ("what does this cover?") are disqualifying.

RLM Corpus Modes
1
Raw Corpus
Model passes text directly — any source the model already holds in context
rlm_query("question", { raw: "full text..." })
2
Thread Corpus
Search the full conversation history — useful for recalling earlier context across turns
rlm_query("question", { threadId: "f50450ee-..." })
3
Thread Tool Corpus
Search a specific offloaded tool output by address — the primary path for large response offloading
rlm_query("question", { threadId: "f50450ee-...", toolKey: "kv_7f3a9b2c" })
