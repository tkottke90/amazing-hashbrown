# Inline SVG's Markdown Sanitize Schema is an explicit enumeration, not `rehype-sanitize`'s `defaultSchema`

Issue #425 needed inline `<svg>` blocks in Markdown to render instead of being escaped — `rehype-raw` parses the raw HTML, and `rehype-sanitize` then decides what survives across the *whole* tree (not just raw-HTML-origin nodes), since chat/wiki content is LLM-authored and untrusted. We considered taking `rehype-sanitize`'s `defaultSchema` and only adding SVG tags on top, but `defaultSchema` also contains ~24 tags with no CommonMark/GFM syntax equivalent (`details`/`summary`, `kbd`, `q`, `ruby`, etc.) that would become renderable as an unplanned side effect of turning on raw-HTML parsing at all. Decided instead to build the Markdown Sanitize Schema (see `GLOSSARY.md`) as an explicit, auditable enumeration of exactly what the existing render pipeline already produces (CommonMark/GFM output, plus `rehype-highlight`'s injected token `<span>`s) plus the new SVG tags — so the allowlist's surface is always an intentional decision, never whatever upstream's default happens to include.

Within that schema: every URL-bearing attribute inside SVG (`href`/`xlink:href`) is restricted to same-document fragment references only — no absolute/protocol-relative URL survives, in any scheme, not just `javascript:` — because an SVG `<image>`/`<use>` pointing at an external URL is a tracking-pixel/read-receipt vector on render with zero script execution required (a plain `<a>` is carved out of this rule — see the design spec — since clicking it is an explicit user action, same trust level as any other Markdown link). SMIL animation elements (`animate`/`animateTransform`/`animateMotion`/`set`) are allowed structurally with no value-bounding enforcement — capping duration/repeat-count would need a separate rehype plugin pass, since a sanitize schema can only allow/deny tags and attributes, not validate their values — an accepted, documented risk for this internal tool. `foreignObject` is excluded with no exceptions, since it's the standard sanitizer-bypass for smuggling arbitrary HTML through an SVG context.

## Considered Options

- **Inherit `defaultSchema` wholesale, add SVG tags on top** — rejected: silently resurfaces raw-HTML tags (`details`/`summary`, `kbd`, etc.) nobody asked for, and ties this codebase's allowlist to upstream's own evolving defaults rather than an intentional, reviewable list.
- **Client-side DOMPurify instead of `rehype-raw`/`rehype-sanitize`** — not pursued; `rehype-sanitize` integrates natively into the existing unified/rehype pipeline already in use (`rehype-highlight`), rather than adding a second, parallel HTML-sanitization library and a `dangerouslySetInnerHTML` escape hatch.
- **Enforce animation duration/repeat-count bounds** — rejected for v1 as disproportionate build cost for an internal, non-public-facing tool with no accessibility-compliance obligation.
