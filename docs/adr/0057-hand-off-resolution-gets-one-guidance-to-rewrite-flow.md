# Hand-off resolution gets one guidance-to-rewrite flow for every cause, not a cap-specific one-off

ADR-0056 needed some way for a human to get an `exhaustion_cap` Handed-Off Run's Task out of `blocked` without just forcing an identical-scope retry. The obvious narrow fix — a dedicated "force retry anyway" action for this one cause — was rejected in favor of something more broadly useful: today, every Handed-Off Run (`agent_requested` or `exhaustion_cap` alike) lands in the same generic "Paused task controls" panel as an ordinary manual pause, its Hand-Off Note visible only unlabeled in run history, with no structured way for a human to respond to it at all.

Decided: the Task Drawer gets a Hand-Off Guidance field, available on any Handed-Off Run's Task regardless of Hand-Off Cause — the standard way a human responds to a hand-off, per this project's composition-over-customization principle, rather than one-off UI built for a single cause. The drawer also surfaces the Hand-Off Note in its own labeled section next to the field, rather than leaving it buried in run history. On save, a one-shot LLM call folds the guidance together with the hand-off's own context (the condensed summary for `exhaustion_cap`, the agent's own note for `agent_requested`) into a rewritten title/description, saved through the existing `PATCH /tasks/:id` path — no new parallel save mechanism. The rewrite changing the title/description is what satisfies ADR-0056's unchanged-scope check and lets an `exhaustion_cap` Task be dragged back to `queue` again; there is no separate override action. If the rewrite call fails, the drawer surfaces an error and leaves the text untouched — it does not silently fall back to appending the raw guidance text. Saving never auto re-enqueues the Task; the human still drags it back to `queue` themselves via the existing Resume mechanism, after reviewing the rewrite.

## Considered Options

- A dedicated "retry anyway, identical scope" override action for `exhaustion_cap` hand-offs — rejected: directly undermines the point of ADR-0056's cap; an edited title/description is an acceptable, deliberate speed bump instead.
- Scope the guidance field to `exhaustion_cap` hand-offs only — rejected: `agent_requested` hand-offs have exactly the same "no structured way to respond" gap today; building it narrowly for one cause is the kind of per-case UI this project's design principles warn against.
- On a failed rewrite, fall back to appending the user's raw guidance text verbatim — rejected: silently changing what was asked for is worse than asking the human to retry the save.
