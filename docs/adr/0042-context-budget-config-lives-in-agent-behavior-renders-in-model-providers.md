# Context-budget setting lives in agent-behavior config, renders on the Model Providers settings page

While designing #354's fix we added a user-facing control for `chat.contextWindow.maxTokens`, so someone running a small local model can lower it and someone on a large cloud model can raise it, rather than leaving the fix's auto-recovery to shoulder a one-size-fits-all global default alone. That field already has working backend plumbing under the `agent-behavior` settings slug's existing `chat: ChatSchema.partial().optional()` patch schema — no schema or route change needed. We considered moving `maxTokens`/`safetyMarginPct` out of `ChatSchema.contextWindow` into the `model-providers` settings section instead, so the backend section and the UI page it's edited from would line up, since the budget is conceptually tied to which model/provider is in use. We rejected the move: it would touch every existing read-site of `env.chat?.contextWindow` (all four agent builds in `chat-agent.ts`) for a UI-placement reason alone, and the `agent-behavior` slug is otherwise the right home for it, alongside the rest of the context-window/trim configuration it belongs with. Instead, the Model Providers settings page UI composes a `maxTokens` field into its Default Provider card and submits it through `agent-behavior`'s own existing PATCH endpoint — a deliberate split between where the value is edited and where it's stored.

## Considered Options

- Relocate `maxTokens`/`safetyMarginPct` into the `model-providers` settings section so the UI page and backend section match — rejected: touches every existing `env.chat?.contextWindow` read-site for a UI-placement reason alone, and fragments `contextWindow`'s config away from the rest of the trim settings it belongs with.
- Put the control on the existing "Agent behavior" settings page instead of Model Providers, matching where the config lives today — rejected: the budget is conceptually tied to the active model/provider, and editing it next to Default Provider is the more discoverable place for that reason.
