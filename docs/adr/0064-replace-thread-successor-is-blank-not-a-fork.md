# Replace Thread's successor is a blank thread, not a checkpoint Fork

The existing `POST /threads/:id/fork` endpoint already copies a thread's LangGraph checkpoint state into a new thread via `forkThreadCheckpoints`, and would have been the obvious thing to reuse for "start fresh in the same workspace." We didn't: Fork's entire purpose is carrying history forward into the new thread's live context, which is exactly the problem Replace Thread exists to escape — an agent stuck insisting on something from accumulated context the user has already corrected. Replace Thread's successor is created with no checkpoint copied at all; continuity is carried solely through the final Workspace Chat Summary, the same mechanism any ordinary new workspace-chat thread already uses to pick up prior context.
