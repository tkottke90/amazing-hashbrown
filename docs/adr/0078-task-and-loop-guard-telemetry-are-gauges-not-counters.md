# Task and Loop-Guard telemetry is exposed as gauges, not counters

The Telemetry Endpoint's first metrics (ADR-0077) are Prometheus counters derived at scrape time, which is safe only while the rows they total are never deleted. The Loop-Guard Escalation, Escalation Outcome, Runs-per-Task, Run-duration and plan-step metrics (`docs/superpowers/specs/2026-11-28-task-hitl-telemetry-design.md`) total data that _is_ deleted: `deleteTask()` removes a Task and its `task_queue` rows, `deleteThread()` removes a thread's `thread_messages` (and with them its HITL prompts), and a Task leaves the "done" set when reopened.

We considered keeping them as counters for consistency with the existing ones, leaving `rate()` and `increase()` available. Rejected: a counter derived from this data would decrease whenever a Task or thread is deleted, and Prometheus reads any decrease as a process restart — silently corrupting `increase()` and `rate()` for the very metrics we'd be inviting people to use them on. We also considered recording each event in-process as it happens (a true counter surviving deletion); rejected for the same reasons as ADR-0077 (a hook in code that has other jobs, lost on restart, a second tally that drifts from stored data).

Decided: expose all of them as gauges of the currently-stored population, named without `_total`, and compute averages as a ratio of two gauges (sum and count) in PromQL. Join-heavy ones (Escalation Outcome, Run duration) are SQL views owned by an `api/` store migration; the rest are plain queries.

**Consequences**: `rate()`/`increase()` are not meaningful on these metrics — graph them as levels. A deletion lowers a gauge instead of producing a phantom reset. Because they are not cumulative, history of deleted Tasks is gone from the series; if durable event history is ever needed, that requires persisting events (an append-only table), not changing the metric type. This also weakens ADR-0077's "no pruning exists" assumption as a general rule: it holds for usage rows and tool-call spans, not for Task, Run or thread data.
