# Archived threads get their own read-only view, not a reused ThreadView

Opening a thread through `ChatRoot`'s normal path calls `switchThread()`, which persists it as `activeThreadId` — the thread you land on next time the app opens. `task`-type threads already avoid this trap by routing to a separate, self-contained `TaskRunView` (takes `threadId` as a prop, never touches `activeThreadId`) instead of `ThreadView`. An Archived Thread needs the same protection: reopening the app must never land you back on a thread you archived specifically to get out of your way. We built a new, small read-only view on the same self-contained shape as `TaskRunView`, rather than adding an "archived-aware" mode to `ThreadView` (which would have made every normal render path carry a branch for a state it otherwise never needs to know about) or reusing `TaskRunView` itself (which renders task-run-specific metadata that doesn't apply to a chat thread).
