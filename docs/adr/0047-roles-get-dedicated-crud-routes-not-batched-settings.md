# Roles get dedicated CRUD routes, not the batched agent-behavior settings section

Sub-agent Roles are a keyed collection a user adds/edits/deletes one at a time — the same shape `tools` and MCP servers already have, and `tools` was explicitly moved *out* of the batched per-section settings PATCH into dedicated CRUD routes (`tool-settings.handlers.ts`, mirrored by `mcp-servers.handlers.ts`) for exactly that reason (see `docs/superpowers/specs/2026-09-13-tool-settings-redesign-design.md` §4/§6). Roles follow that same precedent: `GET/POST /api/v1/roles`, `PATCH/DELETE /api/v1/roles/:name`, rather than joining `agent-behavior`'s batched whole-object PATCH.
