Architecture Overview

System Flows: llm-wiki & rlm

How knowledge retrieval and iterative document querying compose across two distinct thread types.

llm-wiki — wiki operations
rlm — iterative document retrieval
Agent — orchestration & synthesis
Terminal / exit
Stream event — visible in chat
Thread type 1 Conversation with a user

Reactive and user-paced. The wiki is read-only during the turn itself. After responding, the agent checks whether the conversation surfaced novel knowledge and — if so — commits it as a background tool call visible in the stream. No confirmation required.

Thread type 2 Automated task with a specific goal

Goal-directed and multi-step. The agent reads and writes the wiki, uses RLM more liberally for deep research, and commits extracted knowledge back to the wiki after each search cycle as a visible tool call. The loop continues until the goal is met.
