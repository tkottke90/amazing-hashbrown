## RLM

Short for **Retrieval Loop Model** — the mechanism behind the `rlm_query` tool. Instead of dumping an entire long document into the conversation and drowning the model's context in it, the agent searches through it iteratively, a targeted question at a time, until it has enough to answer.

| Key                 | Type   | Default | Description                                                                                                            |
| -------------------- | ------ | ------- | -------------------------------------------------------------------------------------------------------------------- |
| `maxIterations`      | number | `10`    | Maximum search iterations before the agent is forced to give a final answer.                                          |
| `truncateThreshold`  | number | `6000`  | Character count above which `wiki_read_page` truncates its response and tells the agent to use `rlm_query` instead.  |
| `provider`           | string | —       | Name of a provider from `providers` to use for RLM's own model calls. Defaults to `defaultProvider`.                  |
| `model`              | string | —       | Model override for RLM. Defaults to the chosen provider's `defaultModel`.                                             |

{% call code(language="yaml") %}
rlm:
  maxIterations: 10
  truncateThreshold: 6000
{% endcall %}

Pointing RLM at a separate, cheaper or faster provider than the main chat model is a common tuning move once you have more than one provider configured — see the [Overview](/docs/configuration/) page for the `providers` list.
